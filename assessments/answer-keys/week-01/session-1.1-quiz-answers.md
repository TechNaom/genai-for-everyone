# Answer Key — Session 1.1 Quiz

**1.** C — Writing a cover letter draft produces new content. The others (A, B, D) all assign existing input to a predicted label, score, or category — predictive AI.

**2.** Acceptable answer covers: the model predicts the next most statistically plausible token (word/sub-word piece) given everything before it in the input, repeated one token at a time, based on patterns learned from training data — not lookup, retrieval, or guaranteed reasoning.

**3.** B. Note: D is a useful trap — predictive text is famously *not* equally accurate; that's part of the point of the analogy (same mechanism, vastly different scale and quality).

**4.** Confidence in tone is not evidence of correctness. LLMs are trained to produce fluent, plausible-sounding text — fluency and accuracy are not the same property, and there's no built-in mechanism forcing the model to express uncertainty only when it's actually uncertain. (Full grading credit for any answer that identifies this confidence/correctness gap, regardless of exact phrasing.)

**5.** Predictive — "stop fraud" means scoring/classifying transactions as fraudulent or not, which is a classification task, not content generation. (A generative *component* could exist alongside it, e.g. drafting a "transaction blocked" explanation message — but the core ask is predictive.)

**6.** Generative. Input: customer data (name, birthday, purchase history, brand tone guidelines). Output: newly generated personalized email text for each customer — not selecting from a fixed list of templates verbatim (if it is just template-filling with no real generation, that's closer to simple automation — a good answer may flag this ambiguity).
