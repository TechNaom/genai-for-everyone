# Answer Key — Session 7.6 Quiz

**1.** (1) The problem, in one sentence. (2) A live example (real input → real output). (3) One thing that went wrong during building and how you fixed it. (4) Your actual success criteria and whether you met them. (5) What you'd build next.

**2.** Because it demonstrates real judgment and problem-solving ability, not just a feature that happens to work — anyone can show a working demo, but explaining a specific failure and the reasoning behind the fix shows the kind of thinking an employer actually wants to hire for.

**3.** False. The primary audience is a stranger who will never talk to you (a recruiter or hiring manager) and has no prior context — the README needs to explain everything needed to understand the project in about 90 seconds of reading, without assuming program-specific background.

**4.** The one with a full README (screenshot, eval numbers, run instructions) — because a recruiter skimming quickly needs the project's value made instantly visible; a one-line README undersells an equally good project by making it illegible in the short time they'll actually spend looking.

**5.** It's specific and demonstrates real, checkable skill — naming the actual technique (RAG), the actual rigor applied (golden-dataset eval), and the actual safety practice (red-team pass) signals genuine competence, whereas "I used AI" could describe almost anything and signals nothing concrete.

**6.** A tour of every file in the codebase or an explanation of every technology used — demo time is scarce and should be spent on the story (problem, example, hard moment, results, next steps), not an inventory of the codebase.

**7.** A portfolio (a demonstrable, well-documented project) and a vocabulary (the ability to describe your work using specific technique language from the program) — these are described as the program's real output, more important than the certificate itself.
