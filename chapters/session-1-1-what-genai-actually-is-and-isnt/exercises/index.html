Session 1.1 Exercises 15 min, hands-on

Exercises: The AI Capability Map

Build the habit of classifying any "let's use AI" request before writing a single line of code — the single most valuable instinct from this session. This is a pure classification-and-reasoning exercise: no API calls, no paid keys, just plain Python that runs anywhere.

How to run these You'll need Python 3 installed (check with python --version). Download starter.py below, then run it from a terminal with python starter.py. It prints a formatted table and flags any scenario you haven't filled in yet.
starter.py solution.py (reference)

The task

Open starter.py. For each of the 12 scenarios in the SCENARIOS list, fill in three fields. The tell for each row: could the output have been listed in advance (predictive), or is it composed fresh (generative)?

1 Classify the category

For every scenario, set category to either "predictive" or "generative". Ask yourself whether the output is selected from a fixed set of options, or generated new each time.

2 Describe the input → output

Set io_description to a single sentence describing what goes in and what comes out. This is the framing that justifies your category choice, so make it concrete.

3 Name a real tool

Set example_tool to a real product or service that actually does this today (for example, Stripe Radar for fraud flagging, or Midjourney for image generation). Re-run the script after each edit — it counts how many scenarios remain None.

🐞 Task 4 — Debug the Code

A teammate classified this scenario but the script prints WARNING: ... has an invalid category instead of adding the row to the table. Only two values are valid. Find the bug and fix the category so the scenario classifies cleanly.

def validate_and_print():

            continue
        category = item["category"].strip().lower()

Checking your work There's no automated grader — that's intentional. A few scenarios are genuinely debatable at the edges (recommendation systems, for instance, sometimes blend predictive scoring with a generative explanation). The goal isn't perfect agreement with solution.py; it's being able to defend your classification with the input→output framing. Compare your reasoning against solution.py (run it with python solution.py) once you've made a genuine attempt.
