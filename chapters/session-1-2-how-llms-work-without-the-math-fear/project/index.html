Session 1.2 Project 20 min build

Token Cost Estimator

The takeaway build for this session — a small, genuinely reusable tool that turns your new tokenizer intuition into something practical: given any text, how many tokens is it, and what would it cost?

Example run

Output 
=== Token Cost Estimator ===
(rate: $0.5 per 1,000,000 input tokens)

Language   Tokens   Est. cost      Text
----------------------------------------------------------------------
English    7        $0.00000350    Hello, how are you today?
Hindi      24       $0.00001200    नमस्ते, आज आप कैसे हैं?
Japanese   10       $0.00000500    こんにちは、今日は元気ですか？

Takeaway: the Hindi version uses 24 tokens vs. 7 for English — about
3.4x more for the same meaning, and therefore ~3.4x the cost.
How to run Install the tokenizer with pip install tiktoken, then download starter.py below and run python starter.py. It's free, local, and needs no API key.
starter.py solution.py (reference)

What to build

Fill in the three # TODO sections in starter.py:

  • TODO 1 — count_tokens: encode the text and return how many tokens it becomes.
  • TODO 2 — estimate_cost: turn a token count into a dollar cost at the given per-million rate.
  • TODO 3 — loop over the sample texts, print a row for each, and finish with a takeaway comparing the priciest language to English.

Ideas to make it your own

  • Read text from a file or a command-line argument instead of the built-in list.
  • Plug in a real per-token rate for a model you're curious about and compare.
  • Show cost per 1,000 requests, so the language gap becomes dramatic.

Why this project matters

Every time you compare LLM providers on price, you're comparing per-token rates — so tokenization efficiency is literally a line item in a cloud bill. This tiny tool is the exact shape of a real cost check you'll run before shipping an AI feature: take some text, count its tokens, translate that into money.
