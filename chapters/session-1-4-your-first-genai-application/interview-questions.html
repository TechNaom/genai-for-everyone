Session 1.4 Interview Prep 8 min read

Interview Questions: Your First GenAI Application

These map to Section B of the Week 1 set (Sessions 1.3–1.4). Interviewers listen for a clear grasp of API mechanics and statelessness, not memorized definitions.

1 Walk me through what happens, end to end, when your code sends a message to an LLM API and gets a response back.
Strong answer

Your code builds a request — a system prompt plus a list of role-tagged messages (alternating user/assistant turns, ending with the newest user message) — and sends it to the provider, usually as JSON. The provider statelessly runs the model over the entire conversation you sent (it doesn't remember anything between calls on its own) and returns structured JSON: the generated text plus metadata like tokens used and the stop reason. Your code parses the text out of that structure, displays it, and — if the conversation continues — appends both the user message and the assistant reply to its own running history so the next request carries the full context.

Red flags

Describing it as "text in, text out," or assuming the model retains the conversation server-side between calls.

Follow-up

"Where does the actual reply text live in the response?" (Answer: inside the structured object — e.g. response.content[0].text in Anthropic's SDK — alongside metadata, not as a bare string.)

2 What's the difference between the system prompt, the user prompt, and the assistant's previous responses?
Strong answer

System is the developer-set instructions, persona, and rules — set once, invisible to the end user. User is the live human input that changes every turn. Assistant is the model's own prior turns. The key insight is that all three together are what gets sent on each new request, because the model has no memory between API calls — the assistant's earlier replies only stay "in the conversation" because you re-send them.

Red flags

Confusing the system prompt with the user message, or thinking the assistant's past replies are automatically remembered without being re-sent.

Follow-up

"Why is the system prompt usually a separate argument, not just another item in the messages list?" (Answer: it's stable developer-owned configuration, kept apart from the growing user-driven conversation.)

3 A junior developer is confused why their chatbot "forgets" context after just one exchange. What's the likely bug, and how would you explain it?
Strong answer

Almost certainly the code sends only the latest user message each turn instead of the full conversation history. The model isn't being forgetful — it literally never received the earlier exchange, so "make that shorter" arrives as a standalone, contextless message. The fix is to keep one running list of role-tagged messages, append the user's message and the assistant's reply every turn, and send the whole list with each request. I'd explain it with the "consultant with no memory between meetings" analogy: you have to hand over the full transcript every time.

Red flags

Blaming the model's "intelligence" or context window, when the real cause is code that never sends the prior turns; or forgetting that the assistant's own replies must be appended too.

Follow-up

"Which single missing line most often causes this?" (Answer: failing to append the assistant's reply back into the history after each response.)

4 Why does a chat app like Claude.ai or ChatGPT feel like it has persistent memory, when the underlying model is stateless?
Strong answer

The memory lives in the application layer, not the model. Every time you send a new message, the app silently re-sends the entire prior conversation — all previous user messages and assistant replies — bundled with your new message as one fresh request. The model just receives a long block of role-tagged text and predicts what comes next; it has no notion that it's "the same conversation." The continuity you feel is the app faithfully rebuilding and resending context each time.

Red flags

Claiming the model has built-in long-term memory or that past messages are stored inside its weights.

Follow-up

"What's a practical consequence of re-sending everything each turn?" (Answer: long conversations cost more tokens and can eventually exceed the context window, so real apps trim or summarize old turns.)
