Session 1.6 Exercises 30 min, hands-on

Exercises: Build "Explain It To Me Simply"

Integrate everything from Week 1 into one working tool — the predictive/generative distinction (1.1), context shaping (1.2), model choice (1.3), request/response mechanics (1.4), and honest hallucination-risk handling (1.5). The scaffold marks the parts that integrate this week's concepts with # TODO markers.

How to run these Download starter.py below. Run python starter.py with no arguments for an offline self-check (no API key needed). For a live explanation, install the SDK (pip install anthropic python-dotenv), add your key to a .env file, then run python starter.py --topic "black holes" --level beginner.
starter.py solution.py (reference)

The tasks

1 Design the three system prompts

Find the SYSTEM_PROMPTS dictionary and its # TODO. Replace each None with a system prompt full of concrete behavioral instructions for that audience level — banned jargon, required analogy type, assumed background, and target length. Not just "explain simply".

2 Construct the API call

Find the # TODO in explain(). Apply Session 1.4 directly: call client.messages.create(...) with model=MODEL_NAME, max_tokens=400, the level's system prompt, and a single user message asking to explain the topic. Return response.content[0].text.

3 Wire up the honesty flag

Find the # TODO in main(). After printing the explanation, use needs_verification_flag() on the explanation (or the topic) and, if it triggers, print a short, non-alarmist note suggesting the user double-check specific factual claims — Session 1.5's lesson made concrete.

4 Test all three levels on one topic

Run the same topic (e.g. "quantum entanglement") through beginner, professional, and expert. If the outputs are genuinely calibrated — not just shorter/longer — your prompts are doing real work. If they sound suspiciously similar, that's a system-prompt problem, not a code problem: go back and make each level's instructions more specific.

🐞 Task 5 — Debug the Code

This honesty-flag helper is meant to return True when text contains any verification-worthy keyword, but it always returns False. Find and fix the bug.

buggy.py 
FLAG_KEYWORDS = ["study", "percent", "%", "according to"]

def needs_verification_flag(text):
    lowered = text.lower()
    return all(keyword in lowered for keyword in FLAG_KEYWORDS)

print(needs_verification_flag("A 2020 study found 63 percent reacted."))

Hint: the check uses all(), which requires every keyword to be present at once. You want any() — a single matching keyword should be enough to flag.

Checking your work There's no automated grader — that's intentional. Compare your output against solution.py (run python solution.py for an offline demo, or with --compare and a key for all three levels). Your wording won't match exactly, and shouldn't — the goal is that your program runs and that the three levels are genuinely differentiated.
