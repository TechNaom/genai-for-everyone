Session 2.2 Exercises 20 min, hands-on

Exercises: The Few-Shot Classifier Prompt

Build a working few-shot prompt for a company-specific classification task, add one boundary-case example of your own, and prove it actually generalizes — not just that it matches the examples you wrote. This exercise makes a real LLM API call, since testing generalization is the whole point: a prompt that only "works" on the exact tickets used as examples hasn't proven anything.

How to run these You'll need Python 3, plus the Anthropic SDK and a free-tier API key: pip install anthropic python-dotenv. Copy .env.example (repo root) to .env and add your ANTHROPIC_API_KEY. Then download starter.py below and run python starter.py. It classifies five held-out test tickets and prints the results in a table.
starter.py solution.py (reference)

The task

Open starter.py. The support-ticket few-shot prompt from this session's lesson is already there as a starting point — four examples covering Billing, Technical, Account Access, and Other. Your job is to strengthen it and then test it.

1 Add one more few-shot example

Add at least one new example, in the same Ticket: "..." / Category: ... format, before the final placeholder line. The instinct to practice from the lesson: pick something that covers a case the existing four examples don't, rather than a near-duplicate of one that's already there.

2 Test against unseen tickets

Run the script. It sends five test tickets — ones your examples never showed the model — through your few-shot prompt and prints the category each one lands in.

3 Diagnose any misclassification

If a ticket lands somewhere unexpected, the fix is almost never "write a stronger instruction." Ask instead: did any of my examples actually demonstrate this kind of case? That question is the real skill this exercise trains.

🐞 Task 4 — Debug the Prompt

A teammate's few-shot prompt keeps classifying "What's your favorite color?" as Technical instead of Other. Here's their example set. Find the bug and fix it.

buggy_prompt.txt 
Classify the following support ticket into one of: Billing, Technical, Account Access, Other.

Ticket: "I was charged twice for my subscription this month."
Category: Billing

Ticket: "The app crashes every time I try to upload a photo."
Category: Technical

Ticket: "I can't log in, it says my password is wrong even after I reset it."
Category: Account Access

# missing: no example at all shows the model what "Other" looks like

Ticket: "{ticket}"
Category:

With no worked example of the "Other" boundary, the model has never seen what an unrelated, off-topic ticket should map to — so it defaults to forcing every input into one of the three categories it has seen, usually whichever felt closest. Add an "Other" example (like the paddle-boarding one from the lesson) and the misclassification disappears.

classifier.py 
FEW_SHOT_PROMPT_TEMPLATE = """Classify the following support ticket into one of: Billing, Technical, Account Access, Other.

Category: Billing

# TODO: add your own example here, in the same format.

Ticket: "{ticket}"
Category:"""

Checking your work There's no automated grader — that's intentional. Getting all five test tickets right isn't about memorizing those exact five, it's about whether your added example taught a pattern general enough to handle inputs you didn't specifically write for. Compare your choice of example (and your results) against solution.py once you've made a genuine attempt — it explains why its added example was chosen, not just what it is.
