Session 2.3 Exercises 20 min, hands-on

Exercise: Multi-Step Reasoning Prompt

Take a real multi-step business problem, write both a direct prompt and a chain-of-thought version, run both against a real model, and compare the results for accuracy — and for whether the reasoning trail actually holds up to scrutiny, not just whether it looks thorough.

How to run these You'll need Python 3, the anthropic and python-dotenv packages (pip install anthropic python-dotenv), and your own Anthropic API key set as the ANTHROPIC_API_KEY environment variable. Download starter.py below, fill in the two prompts, then run it with python starter.py.
starter.py solution.py (reference)

The task

Open starter.py. A multi-step call-center staffing and cost problem is provided as PROBLEM — it's deliberately built from several compound calculations (a percentage, a subtraction, a multiplication, a division) chosen so that skipping or misordering any single step produces a wrong final answer.

1 Write the direct prompt

Set direct_prompt to the problem text plus an instruction asking only for the final numeric answers — no reasoning steps requested.

2 Write the chain-of-thought prompt

Set cot_prompt to the same underlying problem, this time explicitly instructing the model to work through it step by step before giving a final answer. Keep the problem text identical between both prompts — you're isolating the technique, not rewriting the question.

3 Verify the math yourself

Before trusting either output, work out the correct total cost and capacity percentage by hand or with a calculator. This is the step people skip and the one that makes the exercise actually worth doing — per Session 1.5, a confident answer is not a correct one until you've checked it.

🐞 Task 4 — Compare the failure modes

Run the script and look closely at both responses. A common failure pattern in the direct version is skipping the break-time adjustment to capacity entirely, or applying the 15% abandonment rate to the wrong base number. If your direct response shows one of these errors, does the chain-of-thought version avoid it? If both get it wrong, is it the same mistake in both, or a different one — and what does that tell you about where the model's actual weak point is on this problem?
