Session 2.3 Project 30 min build

Self-Consistency Checker

The Pro path build for this session — implement self-consistency for real: run the same question through a model several independent times, extract a comparable short answer from each response, and detect whether the answers converge or diverge.

Example run

Output 
=== EASY QUESTION ===
Question: What is 12 times 4?

5 runs, extracted answers: ['48', '48', '48', '48', '48']
Tally: {'48': 5}
Majority answer: '48'  (convergence: 100%)
-> High convergence: treat this as a reasonably reliable answer.

=== TRICKY QUESTION ===
Question: A bat and a ball cost $1.10 in total. The bat costs $1.00 more
than the ball. How much does the ball cost?

5 runs, extracted answers: ['$0.05', '$0.10', '$0.05', '$0.05', '$0.10']
Tally: {'$0.05': 3, '$0.10': 2}
Majority answer: '$0.05'  (convergence: 60%)
-> Moderate convergence: worth a second look before trusting it.

Compare the two convergence percentages above. If the easy question
converged much more than the tricky one, that's the self-consistency
signal from this chapter behaving exactly as predicted.
How to run Install the dependencies with pip install anthropic python-dotenv, set your ANTHROPIC_API_KEY environment variable, then download starter.py below and run python starter.py. This one needs a real API key — each run makes ten actual model calls (five per question), which is itself the honest-cost lesson from this session made concrete.
starter.py solution.py (reference)

What to build

Fill in the three # TODO sections in starter.py:

  • TODO 1 — query_n_times: call the model n independent times on the same prompt (with sampling randomness already enabled) and collect the raw response strings.
  • TODO 2 — extract_answer: parse the Final answer: ... line out of each response so answers become comparable short strings instead of full paragraphs. Return "UNPARSEABLE" rather than crashing if a response doesn't follow the format.
  • TODO 3 — check_convergence: tally the extracted answers with collections.Counter, find the majority answer, and compute what fraction of runs agreed with it.
Why two different questions EASY_QUESTION ("what is 12 times 4?") has one unambiguous correct answer — expect near-100% convergence. TRICKY_QUESTION is the classic "bat and ball" cognitive-reflection puzzle: the intuitive answer ($0.10) is wrong, and the correct answer ($0.05) requires actually setting up an equation rather than pattern-matching. Running both side by side is what makes the convergence signal meaningful — a single convergence number means nothing without a comparison point.

Ideas to make it your own

  • Swap in your own genuinely ambiguous question and see how the convergence ratio behaves.
  • Print the full text of any response that disagreed with the majority, so you can actually read where its reasoning diverged.
  • Compute the token/dollar cost of a 5-run check versus a single call, using Session 1.3's per-token pricing framing — make the "honest cost" concrete in real numbers.

Why this project matters

This is self-consistency exactly as described in this session, minus the hand-waving: real independent calls, a real extraction step, and a real convergence number you can act on. It also makes the technique's cost impossible to ignore — this file makes ten actual API calls instead of two, which is precisely the trade-off you're expected to reason about before reaching for self-consistency in a production system.
