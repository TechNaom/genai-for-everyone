Session 2.4 Exercises 20 min, hands-on

Exercises: Resume Parser Prompt

Build the structured-extraction prompt from the lesson, test it against real model output on three sample resumes — including one deliberately missing an email — and implement defensive parsing around it so imperfect output never crashes the program.

Setup — API key This exercise genuinely needs some LLM API to call — there's no way to test a real extraction prompt without one. Install dependencies with pip install anthropic python-dotenv, then copy the repo's .env.example to .env and add ANTHROPIC_API_KEY=your-key-here. The script loads it with python-dotenv; if no key is found it prints a friendly message and exits rather than crashing. Every major provider offers a free tier or trial credits that easily cover the handful of test calls here. No key at all? Read solution.py and trace the prompt and the parsing logic by hand — the reasoning is the point.
starter.py solution.py (reference)

The task

Open starter.py. Fill in two pieces — the prompt template and the defensive parser — then run it against the three sample resumes.

1 Write the extraction prompt

Find EXTRACTION_PROMPT_TEMPLATE. Define an explicit JSON schema with types for name, email, years_experience, and skills. Instruct the model to use null/empty for anything it can't determine rather than guessing, and to return nothing but the JSON object — no preamble, no closing remark.

2 Implement defensive parsing

Find parse_model_json. Try json.loads() directly first. If that raises, try extracting the span between the first { and the last } and parse that instead. If everything fails, return None — never let an exception propagate out of this function.

3 Verify the null case

Run python starter.py and look at Resume 2, which has no email listed. Check that email comes back as null rather than a plausible-looking guessed address. That single check is the most important thing this exercise tests.

🐞 Task 4 — Debug the Code

A teammate wrote this defensive parser, but it still crashes the program on wrapper text. Find the bug: it only tries the direct parse, and re-raises on failure instead of falling back to span-extraction.

buggy_parser.py 
def parse_model_json(raw_text):
    try:
        return json.loads(raw_text)
    except json.JSONDecodeError as e:
        raise e  # bug: this still crashes the caller on wrapper text

Hint: instead of re-raising, attempt the first-{-to-last-} fallback from the lesson, and only return None if that also fails.

Checking your work There's no automated grader for prompt wording — that's intentional. The goal is being able to defend your schema and your fallback logic, not matching solution.py word-for-word. solution.py also adds a validate_schema type-check step, catching the case where JSON parses successfully but a field has the wrong type (e.g. "years_experience": "8 years" instead of 8) — run it with python solution.py once you've made a genuine attempt.
