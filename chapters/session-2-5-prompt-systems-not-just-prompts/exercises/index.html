Session 2.5 Exercises 20 min, hands-on

Exercises: Reusable Prompt Template Library

Build a small library of prompt templates with named variables, clear documentation, and lightweight tests — not exact-match tests, but checks for specific characteristics the output should have. This is a pure template and test-design exercise: no API calls, no paid keys, just plain Python that runs anywhere.

How to run these You'll need Python 3 installed (check with python --version). Download starter.py below, then run it from a terminal with python starter.py. It formats every finished template, runs its test checks, and prints a pass/fail/incomplete count.
starter.py solution.py (reference)

The task

Open starter.py. Three templates are started for you (FOLLOW_UP_TEMPLATE, REFUND_APOLOGY_TEMPLATE, and a blank SHIPPING_DELAY_TEMPLATE for you to write), and two more are left entirely up to you to design.

1 Finish the shipping delay template

Write SHIPPING_DELAY_TEMPLATE so it accepts at least customer_name, order_number, and new_estimated_date. Above the template, add a one-line comment documenting every variable it expects, matching the style already used for the other templates.

2 Design two templates of your own

Fill in CUSTOM_TEMPLATE_1 and CUSTOM_TEMPLATE_2 with any customer-communication theme not already covered (account reactivation, a feature announcement, a subscription-renewal reminder — your choice). Each needs at least two named variables and a documented variable list.

3 Write lightweight test checks

Add a TEST_CASES entry for each of the three templates you completed. Each entry needs sample variable values and a list of check functions — small functions that take the formatted prompt string and return True/False for one verifiable property. contains_customer_name and under_word_limit are provided as examples; write your own for the new templates (e.g. "does it mention the order number," "does it mention the new date").

🐞 Task 4 — Debug the Code

A teammate wrote this check function to verify a template stays under a word limit, but it always returns True even when the instruction is missing entirely. Find the bug and explain why the crude "does the number appear anywhere in the text" approach is fragile, then propose a better check.

buggy_check.py 
def under_word_limit(prompt: str, limit: int) -> bool:
    # Bug: this checks whether the NUMBER appears anywhere in the prompt --
    # it doesn't check the prompt's actual word count, and it would also
    # return True by coincidence if `limit` happens to match an unrelated
    # number already in the template (e.g. a dollar amount or order number).
    return str(limit) in prompt

Checking your work There's no automated grader, and your two custom templates are genuinely open-ended — that's intentional. What matters is that every template has a documented variable list, and every test checks a real, verifiable property of the formatted prompt rather than requiring an exact string match (which is unrealistic for anything an LLM would actually generate). Compare your structure against solution.py (run it with python solution.py) once you've made a genuine attempt.
