Session 3.2 Project 20 min build

Word Counts Alone

The Pro path build for this session — a direct, hands-on follow-up to the Core path exercise's final question: what happens if you rebuild the same 20 sentences' vectors using only raw word counts, with no hand-seeded "concept anchor" topic scores at all?

How to run You'll need Python 3 plus numpy, scikit-learn, and matplotlib installed (the same libraries as the Core path exercise) — run pip install numpy scikit-learn matplotlib if you haven't already. Then download starter.py below and run it from a terminal with python3 starter.py. No API key, no internet access needed: this is a fully offline exercise. It prints a vocabulary size, a vector matrix shape, cosine-similarity sanity checks, and saves a plot to wordcount_only_plot.png.
starter.py solution.py (reference)

What to build

Open starter.py. It reuses the exact same 20 sentences, topic labels, tokenizer, and plotting code as the Core path exercise, so the two plots are a fair, apples-to-apples comparison. Only one function is left for you to fill in.

1 Build word-count-only vectors

Fill in build_wordcount_only_vectors(). For each sentence, build a vector of length len(vocab) where position i counts how many times vocab[i] appears in that sentence — the same raw word-count vector the Core path exercise used as half of its hybrid embedding, except here it's the whole vector. Then L2-normalize each sentence's vector (divide by its own np.linalg.norm), guarding against dividing by zero for any row that happens to be all zeros. No concept-anchor seed score is added at all — that's the entire point of this exercise.

Sanity-check before trusting the plot Once the function is filled in, run the script — it prints cosine similarity for the same four sentence pairs the Core path exercise checked (two pet sentences, a pet vs. a finance sentence, two cooking sentences, two space sentences). Compare the gap between the same-topic pairs and the cross-topic pair against what the Core path exercise printed — it should be noticeably smaller here.

Core comparison

Get the script running end-to-end, then open wordcount_only_plot.png side by side with embeddings_plot.png from the Core path exercise. Do the four topic clusters still separate clearly, or does the clustering largely disappear now that the concept-anchor scores are gone?

What you should see, and why The lesson's prediction is that clustering should largely disappear — not because the math changed (it's the exact same word-count vectors, cosine similarity, and PCA reduction as before), but because these 20 sentences were deliberately written with varied vocabulary even within the same topic ("puppy," "cat," "dog," "parrot," and "kitten" barely overlap with each other despite all being about pets). Twenty short sentences simply don't contain enough raw text for topic structure to emerge from word statistics alone. A real production embedding model doesn't have this problem: it has learned, from billions of words of training text, that those words all relate to the same underlying concept, so clustering by meaning emerges automatically with no human ever hand-seeding topic categories. Scale of training data — not different math — is what makes the difference.

🐞 Common bug — forgetting to guard the zero-vector case

Exactly like the Core path exercise, if a sentence's word-count vector happens to be all zeros (shouldn't normally happen with this fixed sentence list, but is a real edge case any embedding pipeline has to handle for unexpected input), dividing by its norm without a guard crashes with a ZeroDivisionError or silently produces NaN values that quietly corrupt the whole plot. Guard it the same way: check whether the norm is 0 before dividing, and leave the row as zeros if it is.

Ideas to make it your own

  • Try weighting the word-count vector differently (e.g. down-weighting extremely common words like "the" and "a") and see whether that recovers any of the lost clustering without reintroducing hand-seeded topic scores.
  • Write five new sentences of your own, deliberately reusing the same few words within each topic (unlike this exercise's varied vocabulary), and see whether raw word counts alone can cluster them — a live demonstration of how much shared vocabulary actually matters for word-count-only clustering.

Why this project matters

It's easy to walk away from the Core path exercise thinking embeddings work by matching words in disguise — after all, the hybrid vectors did include word counts. This project exists to break that assumption with your own generated output: remove the hand-seeded signal, and the clustering weakens sharply, even though nothing about the underlying math changed. That gap is exactly what separates a small, engineered toy model from a real embedding model trained on a genuinely large amount of text. Understanding why scale matters — not just that it does — is what lets you reason clearly about embedding quality, model selection, and retrieval failures once you're building real RAG systems in the sessions ahead.
