Session 3.3 Exercises 30 min, hands-on

Exercises: Build a Local Vector Store Over a PDF

Take a real PDF — sample_handbook.pdf, a small company employee handbook included in this folder — and build the full retrieval pipeline from this session: chunk it, embed each chunk, store the vectors, and retrieve the top-k most relevant chunks for real test questions. This stops right before generation — Session 3.4 adds that final step. No API key and no internet access required: it reuses the word-count embedding approach from Session 3.2.

How to run these You'll need Python 3, plus numpy and pdfplumber installed (pip install numpy pdfplumber --break-system-packages). Download all three files below into the same folder — starter.py needs sample_handbook.pdf sitting right next to it to run — then run python3 starter.py from a terminal in that folder.
starter.py solution.py (reference) sample_handbook.pdf

Why word-count vectors work here (unlike in 3.2)

Session 3.2's exercise needed hand-seeded "concept anchors" because 20 short sentences didn't share enough vocabulary for plain word counts to show real topic clustering. Today's chunks are full paragraphs of real text, which changes the math: there's simply more shared, topically relevant vocabulary per chunk, so plain word-count vectors produce genuinely useful retrieval without any hand-seeding. You'll verify this yourself — no concept-anchor trick needed this time.

The task

Open starter.py. Fill in four TODOs, in order, to complete the pipeline: chunk_text(), embed_chunks(), cosine_similarity(), and the VectorStore class's add() and search() methods.

1 Chunk the text

Fill in chunk_text(text, chunk_size, overlap): split the extracted PDF text into overlapping word-count chunks. Walk through the word list in steps of chunk_size - overlap, taking chunk_size words at a time, and skip any trailing chunk under 15 words — those are usually leftover fragments at the very end of the document.

2 Embed each chunk

Fill in embed_chunks(chunks, vocab): build a word-count vector for every chunk against the shared vocabulary, exactly like the word-count component from Session 3.2 — a vector of length len(vocab) where each position counts how many times that vocabulary word appears in the chunk.

3 Implement cosine similarity and the vector store

Fill in cosine_similarity() (same formula as 3.2, returning 0.0 for a zero-length vector), then VectorStore.add() (store a chunk and its vector together) and VectorStore.search() (compute similarity against every stored vector, sort descending, and return the top-k (chunk_text, score) pairs).

🐞 Task 4 — Debug the Retrieval

Once your pipeline runs, read the top-1 result for each of the five test questions. One of them — the sick-leave question, "How many sick days do employees get and do they roll over?" — is very likely to retrieve the wrong chunk at the default settings, because PTO and sick leave share a lot of overlapping vocabulary ("days", "year", "employees", "roll over"/"carry over"). Try reducing chunk_size (call run_pipeline("sample_handbook.pdf", chunk_size=30, overlap=5) at the bottom of the file) and re-run. Does the correct sick-leave chunk move up in rank?

Checking your work There's no automated grader — that's intentional. The value is in implementing chunking, embedding, and the search logic correctly and then reading the actual retrieved text for each question, not matching a fixed expected output. For most of the five test questions, the top-1 or top-2 chunk should genuinely contain the answer at the default settings. Compare your implementation against solution.py (run it with python3 solution.py) once you've made a genuine attempt — it includes a fully worked-out Pro path writeup of what changes across different chunk sizes.
