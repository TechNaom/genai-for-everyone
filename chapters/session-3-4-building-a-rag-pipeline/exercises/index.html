Session 3.4 Exercises 30–40 min, hands-on

Exercises: End-to-End RAG App Over a Document Set

Complete the pipeline from Session 3.3: wire format_context(), build_rag_prompt(), and extract_citations() into a single answer_question() function that retrieves, augments, generates, and returns a citeable answer — reusing Session 3.3's vector store as the retrieval layer, over a real 5-page sample employee handbook PDF.

Setup — this one genuinely needs a real API key Sessions 3.1–3.3 were designed to run fully offline. This session is different: generating a grounded answer is the actual point of today's exercise, and there's no meaningful toy substitute for "call an LLM and get a real answer." To run the full pipeline, install dependencies and export your key: 
export ANTHROPIC_API_KEY=your-key-here
pip install anthropic pdfplumber numpy --break-system-packages

Every major provider offers a free tier or trial credits that easily cover the handful of test questions here.
No key yet? The offline_test() fallback You can still do most of the real work offline. format_context() and extract_citations() are pure logic with no API dependency — string formatting and a regex, respectively — and the starter file includes offline_test(), which validates both functions against fake data with no network access required at all. These two functions are most of what this session is actually teaching: get them right first, and you've learned the core lesson even before you spend a single API call. Running python3 starter.py always runs offline_test() first, regardless of whether a key is set, so you get real feedback either way.

The task

Open starter.py. It reproduces Session 3.3's chunking, embedding, and VectorStore code so this file is self-contained, then adds four new pieces to build today.

1 format_context() — the "augment" step

Turn a list of (chunk_text, similarity_score) tuples — the output of VectorStore.search() — into a single numbered context string ready to insert into a prompt. Important: the similarity scores should not appear in the output. They were useful internally for retrieval; the model doesn't need them and they don't belong in the final prompt. Expected format: "[1] {first chunk text}\n\n[2] {second chunk text}", numbers starting at 1.

2 build_rag_prompt()

Fill in RAG_PROMPT_TEMPLATE's two variables (context and question) and return the complete prompt string, ready to send to the model. The template already contains the "ONLY the provided context" instruction, the honest-uncertainty instruction, and the citation instruction — your job is just the string formatting.

3 extract_citations()

Find every citation marker like [1], [2] in the model's answer text, and return a sorted list of the unique chunk numbers cited as integers — e.g. [1, 3] if the answer cited chunks 1 and 3, in any order, possibly more than once each. Hint: re.findall(r"\[(\d+)\]", answer_text) finds all the bracketed numbers as strings; convert to int, deduplicate, and sort.

4 answer_question() — tie it all together

Embed the question with embed_query(), retrieve the top-k chunks with store.search(), format them with format_context(), build the full prompt with build_rag_prompt(), call the model with the provided call_llm(), and extract citations with extract_citations(). Return a dict with "answer", "cited_chunk_numbers", and "retrieved_chunks" (the raw (chunk_text, score) list, so you can manually verify citations against the real chunk text).

Look closely at the third test question in TEST_QUESTIONS — "Does the company offer dental insurance?" — which is deliberately not answerable from the sample handbook. Check: does your finished pipeline say so honestly, or does it generate a plausible-sounding answer anyway? That's the exact behavior the grounding instruction in RAG_PROMPT_TEMPLATE is designed to produce, and it's worth verifying directly rather than assuming the instruction worked.

Checking your work offline_test() passing with no assertion errors is the first checkpoint, and doesn't need a key. With a key: all three test questions should return an answer with at least one citation attached, except the dental insurance question, which should honestly state the information isn't available.
