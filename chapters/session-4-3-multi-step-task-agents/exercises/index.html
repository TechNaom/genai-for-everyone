Session 4.3 Exercises 45–60 min, hands-on

Exercises: Multi-Step Research Agent

Build a research agent that plans a 3-step research strategy, executes it with a tool-calling loop, and stops on its own when it has enough information. This is the core plan-execute-stop pattern from Parts 3 and 6 of the lesson, made concrete. The search tool is simulated so this costs almost nothing to run, but the planning and execution loop itself makes real API calls.

How to run these You'll need Python 3 and the Anthropic SDK: pip install anthropic, plus an API key set as ANTHROPIC_API_KEY (the free tier is enough for this exercise). Download starter.py below, then run it from a terminal with python starter.py.
starter.py solution.py (reference)

The task

Open starter.py. The tool schema, simulated search results, and overall loop skeleton are provided — three TODO sections are left for you to complete.

1 Write the planning prompt

Complete plan_prompt so it clearly asks the LLM to plan 3 research steps for user_task, and explicitly instructs it not to execute yet — just plan. This is the explicit-planning pattern from Part 2 of the lesson.

2 Write the execution prompt

Complete execution_prompt so it tells the agent to now carry out its plan step by step, using the search_web tool.

3 Implement the execution loop

Inside the for iteration in range(max_iterations) loop: extract tool_calls (blocks where block.type == "tool_use") and text_blocks (blocks with a .text attribute) from the response, implement the stopping condition (no tool calls means the agent is done — return working_memory with status = "completed"), and otherwise process every tool call, record each one in working_memory["findings"], and send the tool results back as a new message so the next iteration can see them.

Checking your work There's no automated grader. What matters is that your plan phase never calls a tool (check plan_prompt makes that explicit), your stopping condition correctly fires when the response contains zero tool_use blocks, and working_memory["findings"] has one entry per search actually performed — not more, not fewer. Compare your structure against solution.py (run it with python solution.py) once you've made a genuine attempt.
