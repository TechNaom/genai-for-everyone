Session 4.3 Project 90–120 min build

Fact-Checking Agent

The Pro-path build for this session — a harder version of the plan-execute-stop loop from the exercises, where "enough evidence" is a judgment call instead of a fixed number of searches, and the agent has to deal honestly with sources that disagree with each other.

How to run You'll need Python 3, the Anthropic SDK (pip install anthropic), and an API key set as ANTHROPIC_API_KEY (the free tier is enough). Download starter.py below and run python starter.py. The evidence sources are simulated — a small lookup table that deliberately includes disagreeing statements — so the point of this project is the evidence-handling and judgment logic, not live search results.
starter.py solution.py (reference)

What to build

Fill in the three # TODO sections in starter.py:

  • TODO 1 — the planning prompt: have the agent break the claim into verifiable parts and plan searches for both supporting and contradicting evidence, without searching yet.
  • TODO 2 — the evidence-gathering loop: same tool-calling shape as the exercises/ research agent, but log every raw {query, result} pair rather than guessing whether each one is "supporting" or "contradicting" as it arrives.
  • TODO 3 — the final judgment: ask for one JSON verdict (veracity_score, confidence, supporting_evidence, contradicting_evidence, conflicts, reasoning), parse it defensively, and build a FactCheckResult.

1 Handle a genuinely conflicting claim

Run your agent on "Python is the most popular programming language". The simulated sources for this topic deliberately disagree depending on context (overall index vs. web-development specifically). Your final report should surface that conflict explicitly in the conflicts field — not silently average it away.

2 Add a confidence-based safeguard

Have run_fact_checker print a warning line if confidence comes back below some threshold (e.g. 40) — a low-confidence verdict should be visibly flagged as needing a human to look closer, not presented with the same authority as a well-supported one.

🐞 Task 3 — Debug the Code

A teammate's fact-checker categorized each search result the moment it came back, using this function. It looks reasonable, but it mislabels almost every claim in this project's test set. What's wrong, and why is the final-judgment approach used in solution.py more robust?

buggy_categorizer.py 
def categorize(result: str) -> str:
    # Bug: this only ever looks at ONE keyword and assumes the whole search
    # result agrees or disagrees uniformly. But a single simulated source in
    # this project often contains BOTH a supporting statement and a hedge or
    # disagreement in the same string (e.g. "TIOBE ranks Python most popular...
    # Some rankings show JavaScript more popular in web development"). A
    # per-result keyword check can't split a mixed result into its supporting
    # and contradicting parts -- it just picks whichever keyword appears first.
    if "some" in result.lower() or "however" in result.lower():
        return "contradicting"
    return "supporting"

Ideas to make it your own

  • Swap the simulated SOURCES lookup for a real search API and see how the agent handles genuinely messy, real-world disagreement instead of a scripted one.
  • Add a rule: if confidence is below a threshold, automatically re-run one more targeted search before finalizing the judgment, instead of just flagging it.
  • Log the full evidence trail (plan, every query, every raw result, final JSON) to a file per claim, so you can build a small "fact-check audit log" across multiple runs.

Why this project matters

A research agent that just gathers facts and summarizes them is only doing half the job a real fact-checker does. The harder, more valuable part is handling disagreement honestly — noticing when sources conflict, resisting the urge to average away the tension, and reporting a confidence level instead of false certainty. That's also exactly the shape of judgment a multi-agent reviewer system (Session 4.4) formalizes further, with separate agents specializing in different angles instead of one agent doing all of it.
