Session 4.4 Project 40 min build

Multi-Reviewer System with Convergence Checking

The Pro-path build for this session — a four-agent reviewer-pattern system (writer, fact-checker, style-checker, impact-checker) where the revision loop stops once feedback genuinely stabilizes, instead of always running a fixed number of rounds.

How to run This project makes real model calls — you'll need Python 3, the anthropic package (pip install anthropic), and an ANTHROPIC_API_KEY in your environment. Download starter.py below and run python starter.py. The writer and all three reviewers are already implemented; the point of this build is understanding how they coordinate, then extending the system through the challenges below.
starter.py solution.py (reference)

What to build

Run starter.py as-is first and study how it works, then take on these challenges:

  • Challenge 1 — change convergence_threshold to 0.5 or 0.8. Does the loop stop after more or fewer revision rounds? Why does that direction make sense given what the threshold controls?
  • Challenge 2 — add a 4th reviewer, such as an audience-relevance checker. solution.py shows one worked version of this: an audience_relevance_agent added alongside the other three, folded into both the convergence check and the writer's revision prompt.
  • Challenge 3 — replace similarity_score(), which is a crude word-overlap heuristic, with an LLM-based similarity check (ask the model directly: "are these two pieces of feedback raising substantially the same issues?").

How convergence checking works

similarity_score() compares this round's combined reviewer feedback against last round's, using word overlap (intersection over union of the two feedback strings' word sets). Once that score crosses convergence_threshold, the loop treats the feedback as stabilized — reviewers are largely repeating the same points rather than raising new ones — and stops, even before max_revisions is reached. This is the "define your stopping condition before building" idea from Part 6 of the lesson, made concrete and runnable.

Worth noticing: convergence here is a placeholder heuristic, not a rigorous similarity measure. Word overlap can be fooled by feedback that's paraphrased differently but means the same thing — exactly the gap Challenge 3 above asks you to close.

Ideas to make it your own

  • Try an orchestrator pattern instead: an orchestrator agent assigns "researcher, find data" to a researcher agent, then hands results to a writer agent to synthesize.
  • Try a debate pattern: a pro agent and a con agent argue opposing positions, and a moderator agent synthesizes the disagreement.
  • Persist each run's drafts and feedback history to JSON (json.dump(result, f, indent=2)) so you can inspect it after the fact.
  • Have the writer rank which piece of feedback, across all reviewers, was most important to address first.

Why this project matters

A single reviewer catches some errors; three independent reviewers, each specializing in one concern, catch more — but only if the system also knows when to stop asking for more feedback. Convergence checking is what keeps a multi-reviewer loop from either quitting too early (missing real issues) or running forever (burning API calls on feedback that's stopped meaningfully changing). This is the exact shape of a production reviewer-pattern system: specialized agents, aggregated feedback, and an explicit, testable stopping condition — not just "loop three times and hope."
