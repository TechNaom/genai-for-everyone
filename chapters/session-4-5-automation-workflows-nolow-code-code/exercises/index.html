Exercises: Hybrid Email Categorizer

Build the core-path version of the hybrid pattern from the lesson: a free, instant simple rule catches the obvious cases, and an LLM agent only gets called when the rule genuinely doesn't know — exactly the "rule → agent if unsure → action" shape from Part 4. starter.py already contains a fully worked implementation (marked with TODO 1–4 comments showing where each concern lives) so you can study a complete, working hybrid workflow end to end — the tasks below have you trace it, then extend it, rather than fill in blanks from scratch.

How to run this You'll need Python 3 installed (check with python --version) and the Anthropic SDK, since agent_categorize() makes a real API call: 
export ANTHROPIC_API_KEY=your-key-here
pip install anthropic --break-system-packages
python starter.py
No key yet? simple_categorize() and take_action() are pure logic with no API dependency — you can trace and modify both of those, and the workflow's overall shape, without ever calling the model. Only the emails that fall through to agent_categorize() need a live key.

The task

Open starter.py. It defines three mock emails and a four-part workflow: simple_categorize, agent_categorize, take_action, and workflow (which wires the first three together).

1 Trace the simple rule (TODO 1)

simple_categorize checks for urgent keywords (URGENT, ASAP, ERROR, DOWN, CRITICAL) in the subject or body, then checks whether the sender is a VIP client, returning "urgent" on a match and None otherwise. By hand, trace which of the three MOCK_EMAILS the rule catches on its own, and which one it has to hand off to the agent. Then add one more keyword and one more VIP address of your choosing, and confirm your addition changes the outcome for at least one email you construct yourself.

2 Read the agent's categorization prompt (TODO 2)

agent_categorize only runs for emails the rule couldn't resolve. Read its prompt: it asks for exactly one of urgent/important/normal as plain text, with a fallback to "normal" if the model's response doesn't match one of those three words exactly. Rewrite the prompt to also ask the model for a one-sentence reason alongside the category (you'll need to update the parsing below it too, since the response is no longer a single bare word).

3 Add a fourth action category (TODO 3)

take_action currently handles "urgent" and "important" explicitly, with everything else falling into the "normal"/skip branch. Add a distinct action for a new "spam" category (e.g. [ARCHIVE]), and update agent_categorize's prompt so the model knows spam is now a valid fourth option.

4 Confirm the hand-off contract (TODO 4)

workflow is the piece that actually implements the hybrid pattern: it tries the rule first, and only calls the agent if the rule returned None. Add a fourth mock email designed to force the hand-off (no keywords, not a VIP sender), run the file, and confirm in the printed output that simple_result is None for that email while agent_result is populated — that's the hybrid contract working as intended.

🐞 Task 5 — Debug the Code

agent_categorize validates the model's answer with if result not in ["urgent", "important", "normal"]: result = "normal". A teammate says this is a safe fallback. Explain why it's actually a subtle bug risk: what happens if the model answers with something like "Urgent." (a trailing period) or "urgent, based on the VIP sender" (extra text) instead of the bare word the prompt asked for? Walk through what category that email would silently end up with, and why that's worse than the fallback crashing loudly.

fragile_validation.py 
result = response.content[0].text.strip().lower()
# Bug: any deviation from an EXACT match on one of the three words --
# trailing punctuation, extra explanation text, a capitalized variant
# the .lower() doesn't catch -- silently downgrades a genuinely urgent
# email to "normal", which is the single worst category to guess wrong.
if result not in ["urgent", "important", "normal"]:
    result = "normal"
return result

Checking your work There's no automated grader. What matters is that the hand-off contract holds — the agent is never called for an email the rule already resolved — and that every category you add (spam, or any other) has both a rule/agent path that can produce it and a take_action branch that handles it.
