Session 4.6 Exercises 60–90 min, hands-on

Exercises: Build the Research Agent

The capstone for Week 4: a research agent that takes a topic, plans what to search for, executes those searches, analyzes what it found, and drafts a structured, cited report. It's the single build that needs tool use (4.2), multi-step planning and execution (4.3), and a clear-eyed sense of what an agent should and shouldn't be trusted to do unsupervised (4.5) all at once. There are two paths, and it's worth doing both:

  • Core Path — the four-phase research agent itself: plan → research → analyze → draft.
  • Pro Path — a fact-checking layer on top: draft → fact-check → revise with uncertainty notes.
How to run these You'll need Python 3 and the anthropic package installed (pip install anthropic), plus a valid ANTHROPIC_API_KEY set in your environment. Unlike some earlier exercises, there's no offline stub here — the point of this capstone is watching a real multi-turn agent actually carry context across four live phases, which an offline stand-in can't convincingly fake. Both paths use a small, fixed MOCK_SEARCH_DB instead of a live search API, so the "search" step itself stays free, deterministic, and debuggable while you focus on the workflow.

Core Path: the four-phase research agent

core_path_starter.py core_path_solution.py (reference)

1 Write the planning prompt

Find phase_1_plan() and its TODO 1. Ask the agent for 4-5 specific searches it intends to run, what would make a source credible for this particular topic, and how it plans to structure the eventual report. Specific beats vague here — "search for remote work stuff" is exactly the failure mode this prompt needs to avoid.

2 Extract and execute the searches

Find phase_2_research() and its TODO 2. Build a list of search queries (either parsed from the plan text, or a reasonable fixed set derived from the topic) and call mock_search() for each, storing every result in self.findings so later phases can reference it.

3 Write the analysis prompt

Find phase_3_analyze() and its TODO 3. Ask the agent to identify key themes across the findings, note where sources contradict each other, flag remaining gaps, and rank which sources seem most credible. This phase is what keeps the draft from being a raw dump of search results.

4 Write the drafting prompt

Find phase_4_draft_report() and its TODO 4. Ask for an executive summary, a sectioned main body, key findings, implications, and citations that reference the actual searches — targeting 1000+ words. Because every phase shares self.messages through call_llm(), this prompt doesn't need to repeat the findings from scratch; it can lean on the model's own memory of the conversation so far.

🐞 Task 5 — Debug the Code

mock_search() is supposed to return the entry from MOCK_SEARCH_DB that actually matches the country or topic in the query — but run the four searches from Phase 2 and look closely: do they really return four different results, or does something else happen? Reduced to its essentials, here's the matching logic:

buggy_match.py 
DB = {
    "ai regulation united states": "US_DATA",
    "ai regulation european union": "EU_DATA",
}

def mock_search(query):
    query_lower = query.lower()
    for key, value in DB.items():
        if any(word in query_lower for word in key.split()):
            return value
    return "no results"

print(mock_search("AI regulation trends 2024-2025 european union"))
# prints "US_DATA" -- for a query that's clearly asking about the EU

Hint: any(word in query_lower for word in key.split()) matches on any single shared word, not the whole phrase. Since every query in this agent is built from the same topic string ("AI regulation trends 2024-2025"), every query contains the words "ai" and "regulation" — which are also the first two words of every key in the dictionary. Because the loop returns on the very first match and dictionaries preserve insertion order, the first key ("ai regulation united states") wins for every single query, regardless of which country is actually being searched. The fix has to check for the phrase actually unique to each key (e.g. "united states" vs. "european union"), not just any overlapping word.

Pro Path: research + fact-checking

Once the Core Path runs end to end, this extends it with a second layer: the agent drafts a report, then fact-checks its own claims against a known-answers database, then revises the report to flag whatever it couldn't verify. It's intentionally less scaffolded — you're designing more of the architecture yourself here.

pro_path_starter.py pro_path_solution.py (reference)

6 Trace the fact-checking loop

Open pro_path_starter.py and follow run() through all four steps: research_phase(), draft_phase(), fact_check_phase(), and incorporate_feedback(). Notice that fact_check_phase() asks the model to extract claims worth verifying, then checks those claims against a small fixed FACT_CHECK_DB — a stand-in for a real fact-checking source or search call.

7 Confirm the uncertainty makes it into the final report

Run python3 pro_path_starter.py and read the final output. Confirm that any claim not found in FACT_CHECK_DB is left unmarked as "verified" rather than silently trusted, and that incorporate_feedback()'s prompt explicitly instructs the model to tag unverified claims with [⚠️ UNVERIFIED] and add a "Verification Notes" section — not just quietly revise the wording.

8 Extend it: track a fact-check rate

Add a small summary metric after run() completes: what fraction of extracted claims were found in FACT_CHECK_DB at all (verified or flagged), versus claims the agent made that never got checked in the first place. That gap — claims made vs. claims actually checked — is closer to the real risk in a production fact-checking layer than the verified/unverified split alone.

Checking your work There's no automated grader for either path — that's intentional. For the Core Path, confirm the plan names specific searches, the analysis genuinely synthesizes findings rather than repeating them, and the final report is well-structured, cites its sources, and lands around 1000+ words. For the Pro Path, confirm the fact-check phase actually catches the claims seeded in FACT_CHECK_DB, and that the revised report visibly flags what it couldn't verify instead of presenting every claim with equal confidence. Compare against the *_solution.py files once you've made a genuine attempt — and try to spot the mock_search() bug in Task 5 on your own before reading the hint, since it's the part most worth struggling with.
