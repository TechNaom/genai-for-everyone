Exercises: Bias Audit on Hiring Recommendations

Run a bias audit across three groups (male, female, latino) on 48 sample hiring-recommendation outputs, computing accuracy, representation, and occupational distribution per group — the exact five-step framework from Part 3 of the lesson, in code. This exercise has no API calls and no paid keys: it's plain Python that runs anywhere.

How to run these You'll need Python 3 installed (check with python --version). Download starter.py below, then run it from a terminal with python starter.py. It prints a full bias audit report: accuracy per group, representation per group, and occupational distribution per group, followed by a list of mitigation suggestions.

The task

Open starter.py. Unlike some earlier exercises, there are no TODO blanks here — the BiasAudit class is already a complete, working implementation. Your job for this exercise is different: trace how it works, run it, confirm you understand every number it prints, and then extend it.

1 Trace the three metric methods

Read calculate_accuracy(), calculate_representation(), and calculate_occupational_distribution(). For each, write down in your own words: what does this method treat as "accurate," and what would change the number it reports? (Hint: the accuracy threshold of score > 0.8 is a specific, debatable design choice, not an objective fact.)

2 Add a fourth group

Add a handful of sample outputs for a new group (e.g. "asian") to SAMPLE_OUTPUTS, and re-run the script. Confirm the report picks up the new group automatically without any other code changes — and explain why that works, given how self.groups is built in __init__.

3 Add a severity() helper and a JSON export

Write a severity(gap_pct) function that returns "HIGH", "MEDIUM", or "LOW" given a gap percentage, matching the severity levels used in the lesson's Part 3 sample audit report. Then add a save_report_json() method that writes the accuracy, representation, and occupational-distribution dicts (plus each gap and its severity) to a JSON file, so the audit's findings are machine-readable, not just printed.

🐞 Task 4 — Debug the Code

A teammate's version of calculate_accuracy() divides by len(self.outputs) (the total across every group) instead of len(group_outputs) (just this group's outputs). Explain what number this actually produces instead of accuracy, and why it would make every group's "accuracy" look artificially low and roughly proportional to that group's representation.

buggy_accuracy.py 
def calculate_accuracy(self):
    accuracy = {}
    for group in self.groups:
        group_outputs = [o for o in self.outputs if o["group"] == group]
        accurate = sum(1 for o in group_outputs if o["score"] > 0.8)
        # Bug: divides by the TOTAL sample size, not this group's size --
        # this computes "share of all outputs that were both this group AND
        # accurate," not "accuracy rate within this group." A small group
        # with 100% real accuracy would still show a tiny fraction here,
        # making it look far more biased than it actually is.
        accuracy[group] = accurate / len(self.outputs) if self.outputs else 0
    return accuracy
