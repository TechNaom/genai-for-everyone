Session 6.2 Exercises 15 min, hands-on

Exercises: The Cost Calculator

Build a reusable tool that turns "requests per day, average tokens in and out" into a real dollar figure across model tiers — then use it to quantify one concrete optimization instead of eyeballing it. This is a pure arithmetic exercise: no API calls, no paid keys, just plain Python that runs anywhere.

How to run these You'll need Python 3 installed (check with python --version). Download starter.py below, then run it from a terminal with python starter.py. Once complete, it prints a baseline cost report across three model tiers, then a second report showing the optimized workload side by side.
starter.py solution.py (reference)

The task

Open starter.py. It defines three illustrative model tiers in MODEL_PRICING — small, medium, large — each priced per million tokens, input and output separately (matching Sub-topic 1 of the lesson). Fill in four functions, then a fifth optimization comparison.

1 Cost of a single request

Complete cost_per_request(model, input_tokens, output_tokens). Look up the tier's pricing, divide each token count by 1,000,000, multiply by the matching per-million rate, and add input cost to output cost.

2 Cost of a full day's workload

Complete daily_cost(model, requests_per_day, avg_input_tokens, avg_output_tokens). It's just cost_per_request(...) multiplied by how many requests happen in a day.

3 Compare every tier at once

Complete compare_models(...) to return a dictionary mapping each tier name to its daily cost, so the report can show small vs. medium vs. large side by side.

4 Print the report

Complete print_report(...) to print one line per model tier: the daily cost and the monthly cost (daily × 30). This is the number you'd actually bring to a budget conversation.

🐞 Task 5 — Fix the Optimization Comparison

The __main__ block at the bottom of starter.py prints a baseline report, then is supposed to print a second report for the same workload with avg_input_tokens trimmed from 1500 down to 600 (representing a tighter, less wasteful prompt) — and finally print the exact monthly dollar savings that trim produces on the "medium" tier. Right now it just raises NotImplementedError. Replace that with a second call to print_report(...) using the trimmed input token count, then compute baseline_medium and optimized_medium with daily_cost(...) and print the difference × 30.

what-to-add.txt 
print_report(requests_per_day=50_000, avg_input_tokens=600, avg_output_tokens=300)

optimized_medium = daily_cost("medium", 50_000, 600, 300)
monthly_savings = (baseline_medium - optimized_medium) * 30
print(f"Medium-tier monthly savings from prompt trimming: ${monthly_savings:,.2f}")
