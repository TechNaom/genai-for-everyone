Session 6.3 Exercises 20 min, hands-on

Exercises: The Model Adapter

Build a thin adapter layer over two mocked model providers, then run the same task across both and compare cost, latency, and quality — the exact habit that makes switching providers (or adding a fallback) cheap later instead of a codebase-wide rewrite. This is a fully offline exercise: no API key, no internet access, no external libraries needed.

How to run these You'll need Python 3 installed (check with python --version). Download starter.py below, then run it from a terminal with python starter.py. It compares the two mocked providers directly, then runs the fallback wrapper several times so you can watch it trigger.
starter.py solution.py (reference)

The task

Open starter.py. Two mocked providers are already defined: provider_a (strong, but simulates a 30% outage rate) and provider_b (faster, cheaper, and always available). Both return a dictionary with the same shape — text, cost, and latency_ms — which is exactly the consistent-return-shape contract the lesson's adapter section calls out. Your job is to finish the adapter functions.

1 Implement call_model

Look up the requested provider name in the PROVIDERS dictionary and call it. If the name isn't recognized, raise a ValueError that names the unknown provider — don't let it fail silently or return None.

2 Run the same task across both providers

With call_model working, the starter's __main__ block already calls both provider_a and provider_b with the same prompt. Run it a few times — because provider_a has a simulated 30% outage rate, some runs will show it failing while provider_b keeps succeeding.

3 Build the comparison table

Fill in build_comparison_table(): call each provider once, and for each one, record its cost, latency_ms, and a one-line subjective quality_note (a short, honest opinion — e.g. "solid, slightly slower" or "fast, terser answers"). Print the three side by side so a real cost/latency/quality trade-off is visible at a glance, not just individual print statements.

🐞 Task 4 — Debug the Code

A teammate wrote this version of the provider lookup. It never raises an error for an unknown provider name — it just silently returns None, which then crashes two functions later with a confusing AttributeError instead of a clear message. Find the bug and fix it so an unknown provider fails loudly and immediately.

def _call_provider_a(prompt: str) -> Dict:
    """Mock 'strong but occasionally unavailable' provider."""
    if random.random() < 0.3:  # simulate a 30% outage rate for the exercise
        raise ConnectionError("provider_a: simulated outage")
    time.sleep(0.05)
    return {"text": f"[provider_a] answer to: {prompt}", "cost": 0.02, "latency_ms": 50}

def _call_provider_b(prompt: str) -> Dict:
    """Mock 'faster, cheaper, slightly weaker' provider."""

    return {"text": f"[provider_b] answer to: {prompt}", "cost": 0.005, "latency_ms": 20}
