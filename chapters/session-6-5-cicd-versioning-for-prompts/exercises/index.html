Session 6.5 Exercises 15 min, hands-on

Exercises: The CI Regression Gate

Build the check that a real CI pipeline would run on every pull request that touches a prompt: score a new version against a golden dataset, compare it to a stored baseline, and return pass/fail with a message — the same shape as a real CI job's exit code. No API calls, no paid keys, just plain Python that runs anywhere.

How to run these You'll need Python 3 installed (check with python --version). Download starter.py below, then run it from a terminal with python starter.py. It raises NotImplementedError until check_regression is filled in.
starter.py solution.py (reference)

The task

Open starter.py. There's one function to complete: check_regression(new_version, baseline_version, threshold_drop=0.05). The tell for the whole exercise: compare against the last known-good baseline, not a fixed absolute number — a new version could clear an absolute bar while still being meaningfully worse than what it's replacing.

1 Score both versions

Use the provided mock_score_prompt to get a score for new_version and for baseline_version. In a real pipeline this would run each prompt against the GOLDEN_DATASET and grade the responses — exactly Session 5.1's regression suite, just wired to run automatically.

2 Compute the drop and the verdict

Compute drop = baseline_score - new_score. Set passed to False if the drop exceeds threshold_drop, otherwise True. A negative drop means the new version actually scored higher — that should always pass.

3 Build a clear CI-log message

Return a dict with new_score, baseline_score, passed, and a one-line message string that states both scores, the drop, and the threshold — something you'd actually want to read in a real CI log at 2am.
