Session 7.3 Exercises Runs alongside your build, hands-on

Exercises: Build the Checkpoint Tracker

There's one exercise this session: a checkpoint tracker script you'll use for real, alongside whatever capstone project you're actually building today. There's no core/pro split into separate files — instead the pro path is a harder variant of the same tracker:

  • Core path — log start/finish times for Checkpoints 1–3 and get a formatted status report.
  • Pro path — require a justification note for each checkpoint before it can be marked complete.
How to run this You'll need Python 3 — that's it. Everything in starter.py runs with the standard library; no API key, no pip install of anything extra. This isn't a graded exercise about a mock system — it's a real tool. Use it while you build your actual capstone this session, calling complete_checkpoint() each time you actually hit a checkpoint.
starter.py solution.py (reference)

1 Log checkpoints as you build (Core path)

Find BuildDayTracker and implement complete_checkpoint() (TODO 1): append a dict with the checkpoint name, the current elapsed_percent(), and the optional justification to self.log. Then implement status_report() (TODO 2): return a formatted string listing each logged checkpoint and the elapsed percent at which it was completed.

2 Flag a late Checkpoint 1

status_report() should specifically flag Checkpoint 1 if it was logged after 25% of your build time elapsed — the "you should have simplified" signal from the lesson. Look at CHECKPOINTS[0] and the 25 threshold mentioned in the TODO comment.

3 Pro path — require a justification

Extend complete_checkpoint() so a missing or empty justification raises instead of silently logging None. Then, while you actually build today, write one honest sentence per checkpoint justifying why you're moving on now rather than polishing further — the scope-discipline judgment call from the lesson's Pro path challenge.

Checking your work There's no automated grader, the same way a real build day doesn't come with one either. Confirm instead: complete_checkpoint() records the elapsed percent at the moment it's called, and status_report() correctly warns when Checkpoint 1's logged elapsed_percent is over 25. Compare against solution.py once you've made a genuine attempt.
Optional extension Once the core path runs, try the pro path variant above — and keep the tracker running for the rest of today's build. A justification written in the moment, before moving to the next checkpoint, is a very different (and more honest) exercise than one written afterward from memory.
