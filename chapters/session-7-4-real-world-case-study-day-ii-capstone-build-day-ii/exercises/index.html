Session 7.4 Exercises 30–45 min

Exercises: Case Study Worksheet + Peer Review

One exercise, two paths. The core path is the second Case Study Analysis Worksheet, applied to the Contract Review Assistant from today's lesson. The pro path is a harder, writing variant of the same underlying skill: instead of analyzing someone else's system on paper, you run a peer-review checklist against your own capstone (or a classmate's) and write up real findings.

How to run this Everything here is Python standard library and plain text — no API key, no pip install. The core path is pure writing (no code to run at all); the pro path has one small script, starter.py, to implement and run.
case_study_worksheet.md starter.py solution.py (reference) filled_worksheet_example.md (reference)

1 Core path — fill in the case study worksheet

Open case_study_worksheet.md and answer all four questions in your own words, based on the Contract Review Assistant case study from the lesson: why no auto-approval path exists, what actually caused the near-miss, the fix and its trade-off, and one lesson applied concretely to your own capstone's design. Compare against filled_worksheet_example.md once you've made a genuine attempt.

2 Pro path — run the peer-review checklist

Find peer_review() in starter.py and implement it: given a project name and a dict mapping each CHECKLIST_ITEMS entry to True/False, return a formatted report showing which items pass, which need attention, and an overall readiness percentage. Fill in example_answers with your own honest answers about your actual capstone v1 — or hand the same checklist to a peer and use theirs — then run:

terminal 
python3 starter.py

3 Write up your findings

Beyond the printed report, write down: one thing that's working well in the reviewed capstone, one specific risk you'd want addressed before it went further, and whether the success criteria from the Session 7.1 proposal are actually being measured yet — or just assumed.

Checking your work There's no automated grader for either path, the same way there's no automated grader for a real case study analysis or a real peer review. Confirm instead: your worksheet answers are specific to this case study (not generic restatements of "human review is good"), your peer_review() output correctly separates ✅ items from ⚠️ items and computes the right readiness percentage, and your written findings name one concrete risk rather than a vague "looks fine." Compare against solution.py and filled_worksheet_example.md once you've made a genuine attempt.
