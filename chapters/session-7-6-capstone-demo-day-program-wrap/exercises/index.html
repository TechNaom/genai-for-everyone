Session 7.6 Exercises 30–45 min, hands-on

Exercises: Write the Portfolio README

One build for this session: write your capstone's portfolio README following the structure from the lesson, and check it against the required elements. There's no core/pro code split — the checker script is the same either way, and the "pro path" is a harder version of the same task rather than a separate program.

  • Core path — write PORTFOLIO_README.md for your capstone, run the checker, and time a written demo script against the five beats.
  • Pro path — deliver the actual 5-minute demo (to a peer, mentor, or recorded for self-review), and get feedback on whether the problem was clear in the first 30 seconds, whether the "what went wrong" moment was concrete, and whether success criteria were real numbers.
How to run this You'll need Python 3 — that's it. Everything in starter.py runs with the standard library; no API key, no pip install of anything beyond what ships with Python. The checker doesn't grade your writing — it just confirms the five required sections are present, the same low bar a recruiter's 90-second skim effectively applies.
starter.py solution.py (reference) example_portfolio_readme.md (reference)

1 Write your portfolio README

Write PORTFOLIO_README.md for your actual capstone (or adapt example_portfolio_readme.md as a shape to follow if your capstone isn't finished yet). It needs, in order: what the project does and for whom, a way to see it work (a screenshot, a GIF, or a live demo link), what techniques it uses and why, your actual eval numbers, and how to run it.

2 Implement the checker

Find check_readme() in starter.py and implement it: for each section in REQUIRED_SECTIONS, check case-insensitively whether any of its keyword list appears in the README text, and return a dict of {section_name: True/False}.

3 Run it against your own README

Run python3 starter.py PORTFOLIO_README.md. Fix whatever comes back ⚠️ missing until all five sections pass. This checker is intentionally shallow (keyword matching, not genuine judgment) — the real bar is still whether a stranger could understand your project in 90 seconds, not just whether a script matched some words.

4 Write and time your demo script

Write out your 5-minute demo following the five beats from the lesson: the problem in one sentence, a live example, one real thing that went wrong and how you fixed it, your actual success numbers, and what you'd build next. Read it aloud and time it — if it's running long, the first thing to cut is anything that sounds like a tour of your codebase rather than the story.

🐞 Task 5 — A README that would pass the checker but still fail a recruiter

The checker is a keyword match, not a judgment call — it's easy to game and still write a bad README. For example, a README containing the sentence "no screenshot, no eval numbers, just run it" would technically trip the evidence_it_works and eval_numbers keyword checks (it contains the words "screenshot" and "eval") while communicating the exact opposite of what those sections are supposed to prove. Read your own PORTFOLIO_README.md after it passes the checker and ask honestly: does it actually show a screenshot and real numbers, or does it just mention the words? The checker catches missing sections; it can't catch a hollow one.

Checking your work There's no automated grader for the writing itself, the same way there's no automated grader for whether a recruiter is actually convinced. Confirm instead: starter.py reports 5/5 on your real PORTFOLIO_README.md, every section contains genuine content (not just a keyword that happens to match), and your demo script hits all five beats within 5 minutes when read aloud. Compare check_readme() against solution.py once you've made a genuine attempt.
Optional extension (Pro path) Once your README passes and your demo script is timed, actually deliver the demo — to a peer, a mentor, or recorded for self-review — and get feedback on three specific things: was the problem statement clear in the first 30 seconds, was the "what went wrong" moment concrete and specific rather than vague, and were the success criteria stated as real numbers rather than impressions.
