# Session 3.6 Quiz — Answer Key

1. **B.** Retrieval can confidently return a chunk from the *wrong document entirely*, not just an imprecise chunk from the right one. With one document, every retrieved chunk is at least from "the right place" by definition. With multiple cross-referencing documents, a chunk from the wrong source can still score highly if it happens to mention related terms in passing.

2. **B.** Blank-line-based chunking merges an entire multi-section document into one diluted chunk, because PDF text extraction doesn't reliably preserve blank lines between sections. The Registration Guide's five sections collapse into a single ~240-word chunk, and changing `target_words` doesn't fix this because the underlying paragraph split never finds more than one "paragraph" to work with in the first place.

3. **Sample answer:** A fix built for one document's structure (e.g. splitting on numbered headers like "1. Eligibility") only works if the new document actually uses that same structure. This lab's documents use ALL-CAPS headers on their own line instead of numbers, so a numbered-header regex would find nothing to split on and the bug would persist unchanged. Before assuming any fix transfers, you should inspect the actual extracted text of the new document — print out a sample, look at exactly how its section boundaries appear after PDF extraction — rather than assuming a previously successful fix will generalize.

4. **B.** Lines that are entirely uppercase, since that's how this corpus's section headers are written. The regex splits right before a line matching that all-caps pattern, which survives PDF text extraction intact even though blank lines do not.

5. **Sample answer:** Real policy documents naturally cross-reference related topics even within sections that aren't primarily about them — the Registration Guide's course-load section mentions "full-time" status and financial aid eligibility, and its registration-holds section explicitly name-drops the Academic Standing Policy. When all five of the Registration Guide's sections get merged into one chunk, all of that cross-referencing language ends up concentrated together, so the merged chunk's bag-of-words vector contains many of the same terms a probation- or housing-related query would use — without actually containing the specific facts (the 13-credit-hour limit, the 30-day move-out window) those questions are asking about.

6. **Sample answer:** The transferable lesson isn't "split on all-caps headers" — that's specific to this corpus. The actual principle is that there is no universal chunking fix, only a universal chunking *process*: look at how your real documents are actually structured after going through whatever extraction pipeline you're using, identify a pattern that reliably survives that extraction, and verify your fix actually works by running it against real test questions — rather than assuming a fix that worked on a previous document set will automatically work on a new one with a different formatting convention.
