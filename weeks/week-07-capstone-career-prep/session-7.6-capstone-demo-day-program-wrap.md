# Session 7.6: Capstone Demo Day & Program Wrap

**Week:** 7 (Capstone Career Prep)
**Format:** Live session + self-paced exercise + quiz

## Learning objective

Present your capstone in a demo format that actually lands with an audience, and write a portfolio README that makes the project legible to a stranger — a recruiter, a hiring manager, or a future you six months from now.

## Concept (shared by everyone)

Seven weeks of building comes down to a few minutes of demo, and separately, to whatever's left in your GitHub repo after the program ends. Both need to be optimized deliberately — neither happens well by accident.

### The demo: structure beats improvisation

A strong 5-minute capstone demo follows a tight shape:
1. **The problem, in one sentence** (not "let me show you my architecture")
2. **A live example**, showing real input → real output
3. **One thing that went wrong during building, and how you fixed it** — this is the single highest-signal moment in most demos, because it shows judgment, not just a working feature
4. **Your actual success criteria and whether you met them** (numbers, not vibes)
5. **What you'd build next**, if you had another week

Notice what's *not* in this list: a tour of every file in your codebase, or an explanation of every technology used. Demo time is scarce; spend it on the story, not the inventory.

### The portfolio README: written for someone who will never talk to you

Six months from now, a recruiter finds your repo, reads it for 90 seconds, and decides whether to reach out. That README needs, in order: what the project does and for whom (one paragraph), a way to see it work (a screenshot, a GIF, or a live demo link — text alone undersells a working project), what techniques it uses and why (your Session 7.1 language, refined), how you evaluated it (your actual numbers), and how to run it themselves (your Session 6.6 `DEPLOY.md` pattern). This is the same discipline as every session doc in this program: concept, then evidence, then how to actually use it.

### Career next steps

The program's real output isn't a certificate — it's a portfolio and a vocabulary. Concretely, before you consider this "done": your capstone repo has a real README (above), your resume or LinkedIn references the specific techniques you used (not "AI," but "built a RAG pipeline with a golden-dataset eval and a red-team safety pass" — the language from Weeks 3 and 5), and you've identified one or two follow-up projects that would extend this work, so the learning doesn't stop at demo day.

## Core path — guided activity

Write your capstone's portfolio README following the structure above, and prepare your 5-minute demo script (the 5 beats above, timed). Run the README checker to confirm all required elements are present. Full instructions: [`codebase/exercises/week-07/session-7.6/`](../../codebase/exercises/week-07/session-7.6/).

## Pro path — extended challenge

Deliver the actual 5-minute demo (to a peer, mentor, or recorded for self-review) and get feedback specifically on: was the problem statement clear in the first 30 seconds, was the "what went wrong" moment concrete and specific, and were the success criteria stated as real numbers rather than impressions.

## Real-world scenario

Two capstones are equally good technically. One repo has a one-line README saying "RAG chatbot, run `python app.py`." The other has a paragraph on the problem, a screenshot of it working, the eval numbers, and clear run instructions. A recruiter skimming GitHub profiles for 90 seconds each will remember the second one — and that's the entire game of a portfolio, regardless of how good the code underneath actually is.

## Key takeaways

- A strong demo has five beats: problem in one sentence, live example, one real thing that went wrong and how you fixed it, actual success numbers, and what's next — not a tour of every file.
- A portfolio README is written for a stranger who will never talk to you — it needs to answer "what is this, does it work, and how do I run it" in under 90 seconds of reading.
- Describing your project using specific technique vocabulary (RAG + golden dataset + red-team pass) demonstrates real skill in a way that "I used AI" never will.
- This program's real output is a portfolio and a vocabulary you can use in an interview — the certificate is secondary to both.
